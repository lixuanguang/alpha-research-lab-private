B07 bounded bootstrap wheel admission, 2026-09-04

Scope: revise the proposed ADR 0012 and B07 admission implementation to permit
authenticated publication evidence for isolated development/CI when an exact native
package lacks a PyPI sdist. No dependency is installed or admitted by this change.
The record explicitly says source-to-wheel binding is unverified. It is neither
SLSA certification nor an artifact-release or production exception.

Authority and risk: maintainer-requested revision on the solo-bootstrap track.
A04 R2: no capital, shared-domain and shared-data/library materiality, shared-sensitive
security boundary, compatibility-window rollback, computational materiality and no
economic/model/trading trigger. QG01-QG06 and QG09-QG14 remain applicable. B08's QG15
artifact-boundary regression is covered as additional diagnostic evidence.
Code Owner, independent domain, Platform/SRE and Security review remain unavailable.

Controls: separate optional bootstrap_wheel_admissions records require an exact native
package/version, immutable source revisions/hashes/licenses, complete locked wheel
coverage, trusted-root and per-wheel bundle hashes, and exact signer/issuer.
The same Cosign 3.1.3 verification checks claims and transparency. Only in-toto v1
PyPI publish statements with the exact subject and null/empty predicate are accepted.
Malformed sdist, signature failure, unsupported source or incomplete lock never falls
back to a weaker path. The existing signed-build profile still rejects publication.

Each bootstrap record has Platform ownership, a unique B07-DEP-NNN finding, explicit
residual risk and closure, a review window no longer than 30 days and no later than
the parent policy review deadline, and four nonempty digest-bound retained reports:
source review, security review, native inventory and compatibility results. Report
content remains reviewable evidence, not independently authenticated approval.
Unknown scope, falsely claimed build binding, missing evidence, unsafe paths, stale
or future reviews, and overlapping admission profiles fail closed. CLI success
displays each active package's unverified binding, owner, finding and expiry.

Release boundary: B08 depends on the B07 release guard before artifact creation,
before any signing tool call and during verification/publication. Any bootstrap
record blocks the entire graph. Removing a record alone cannot release the same
unprovenanced dependency: the guard checks the Python graph and all admitted lock
hashes again. No workflow permissions, credentials, signer or registry changes occur.
The governed dependency edge and Bazel read inputs are updated together.
